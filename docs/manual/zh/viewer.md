# 查看器

`V` 在查看器中打开文件（自动预览 Autoview，即 F7，则将其显示在文件列表旁）。二进制文件默认以十六进制模式打开。磁盘上的大文件不会整个读入：查看器随屏幕移动读取屏幕上显示的内容（参见[大文件](#大文件)）。无法这样读取的文件只显示开头部分，最多到大小限制。
电子表格、CSV、DBF、SQLite 和 Parquet 以表格形式打开（见[表格](tables.md)）。

| 按键 | 功能 |
|---|---|
| ↑ ↓ PgUp PgDn Home End | 上下滚动 |
| ← → | 左右滚动 |
| `H` | 下一个模式：文本和十六进制；在 Markdown 文件中为渲染、文本和十六进制 |
| `O` | 切换到下一种编码（UTF-8、CP850、1252、CP437、1251、KOI8-R、UTF-16） |
| `C` | 开启或关闭语法高亮 |
| `W` | 开启或关闭软换行 |
| `#` 或 `L` | 开启或关闭行号（在文本模式下） |
| `g` 或 `:` | 跳转到指定行（在十六进制模式下为字节偏移量，在表格模式下为表格行） |
| `&` | 只显示匹配的行，纯文本或正则表达式（[筛选行](filter.md)）；表格模式下为 SQL 筛选 |
| Ctrl+B | 为显示的每条记录或每行输出一行（[查看器中的批处理](execute.md)） |
| `E` | 编辑文件；返回 Xylem 后，查看器会在同一位置显示更新后的内容（二进制文件仅在 [`[editors]`](execute.md) 中配置了对应编辑器时可用） |
| `D` | 开启 Git 时：显示自上次提交以来的更改，再次按下返回原内容（[Git](git.md)） |
| `T` | 在以表格形式打开的文件中，切换表格和文本；在 Markdown 文件中，切换渲染和源文本 |
| `U` | 在已标记文件视图（Ctrl+V）中：取消标记该文件 |
| `y` 或 Ctrl+Insert | 将文件路径复制到剪贴板 |
| Esc | 关闭查看器 |

## 搜索

**F** 从文件开头向后搜索，**B** 从文件末尾向前搜索，**/**（或 `S`）从当前页向后搜索，**\\** 从当前页向前搜索；**Space** 沿同一方向继续查找下一个，**+** 和 **-** 选择搜索方向。匹配项会高亮显示。在搜索提示行中，按 **F2** 切换是否区分大小写（忽略大小写时，带重音符号的字母同样不区分大小写，如 `AÇÃO` 可匹配 `ação`），按 **F4** 在文本与十六进制（如 `4d 5a` 这样的字节对）之间切换。搜索词中间的 `*` 可匹配同一行内的任意内容（如 `error*disk`）。

**F3** 切换搜索方向，因此只用 F 也能完成 B 的功能：从开头向前搜索，或从末尾向后搜索。

## 语法高亮

支持约 150 种语言的源代码和脚本着色（Rust、Python、shell、C、JavaScript、SQL、YAML、Markdown 等），可通过扩展名、文件名（如 `Makefile`）或首行（如 `#!/bin/bash`）自动识别。默认开关由 `syntax_highlight` 设置（见 [配置](configuration.md) 第 2 页）。高亮颜色在当前主题背景上始终保持清晰易读，且仅对前 20,000 行进行语法着色，超过 10,000 个字符的行也不着色，因此超大文件也绝不会拖慢查看器的速度。

## 渲染的 Markdown

`.md` 和 `.markdown` 文件以渲染方式打开，在 Autoview、归档内和压缩文件（`x.md.gz`）中也是如此，边框上显示 `RENDERED`。`T` 在同一位置显示源文本，再按一次返回；`H` 依次切换渲染、文本和十六进制。

可以看到标题、粗体、斜体、删除线、代码、带语法高亮的代码块（`C` 关闭高亮）、嵌套和编号列表、任务列表（`[x]`）、引用、水平线和表格。不会下载任何内容，链接也不会打开任何东西：

- 链接在文字旁边显示真实地址，例如 `safe <https://example.com>`，文字无法冒充另一个地址。
- 图片是一行文字：`[image] 说明 <photo.png>`。
- Mermaid 图是标为 `mermaid` 的代码块。
- HTML 和 HTML 注释保持为可见文本。
- 文件开头的 YAML 块是标为 `yaml` 的代码块。

文本总是适应窗口，因此 `W` 在这里不起作用；← → 可以到达过宽表格的列。搜索查看屏幕上的文本，包括地址，也能找到跨行的短语。`g` 和 `#` 按源文本的行计数。Ctrl+B 作用于源文本的所有行。`&` 切换到文本模式并在其中过滤。

超过 8 MiB 的文件以源文本打开，并显示提示。渲染也会在时间限制（3 秒，Autoview 中为 100 毫秒）或内存限制处停止，此时标题栏显示 `(rendered only the start)`。表格最多显示 256 列。控制字符显示为 `·`，包括写成实体的控制字符，例如 `&#27;`。

Markdown 本身会隐藏一些内容：没有被使用的链接定义，以及超出表头列数的单元格。要查看全部内容，请按 `T` 显示源文本。斜体和删除线取决于终端及其字体，因此它们也有自己的颜色。

## JSON、YAML 和 TOML

`.json`（还有 `.geojson`、`.har`、`.webmanifest`，以及允许注释和末尾逗号的 `.jsonc` 和 `.json5`）、`.yaml` 或 `.yml`，以及 `.toml`（还有 `Cargo.lock`）会以可折叠的树打开，边框显示 `TREE: JSON`。压缩成一行的文件也和其他文件一样容易阅读。不超过 2,000 个节点的树会全部展开；更大的只显示第一层。

| 按键 | 操作 |
|---|---|
| ↑ ↓ PgUp PgDn Home End | 移动光标 |
| → | 展开节点（再按一次：进入节点） |
| ← | 折叠节点，或回到上一级节点 |
| `Enter` | 展开或折叠节点 |
| `*` | 展开该节点下的全部内容 |
| `k` | 复制节点的路径：JSON 中为 `.servers[2].name`，YAML 和 TOML 中为 `servers.2.name`。含换行符、控制字符或文字方向字符的键会加上引号，并把这些字符转义（`\n`、`\u202e`），这样把路径粘贴到 shell 中绝不会执行其中的某一行 |

页脚显示光标所在节点的路径。搜索（`F`、`B`、`/`）会查找键和值，包括折叠的节点内部，并展开通往结果的路径。`T` 显示该节点所在行的文本，再按一次返回；`H` 在树、文本和十六进制之间切换。`&`、`g`、`#` 和 Ctrl+B 作用于文本的各行。

- 折叠的节点会说明它包含什么：`{12 keys}`、`[340 items]`。
- 数字按文件中的写法显示：`12345678901234567890` 保持原样，TOML 中的 `1_000` 也一样。
- 字符串中的换行显示为 `↵`。
- 同一对象中出现两次的键会显示两次，标记为 `dup key`，标题栏会统计数量。不同程序对哪一个生效看法不一，这可能在审查时藏住一个值。
- YAML 锚点显示为 `&a1`，别名显示为 `*a1`：别名永远不会展开，因此一个专门用来自我膨胀的文件（"billion laughs"）的代价不会超过它本身的文本。标签（`!Ref`）显示在值之前。多个文档放在同一个根下，名为 `document 1`、`document 2`……

无效的文件，或嵌套超过 512 层的文件，会以文本打开，提示会说明原因和所在行。树是用整个文件构建的：超过读取上限的文件以文本打开。树在达到 2,000,000 个节点（约 170 MiB 内存）或构建耗时过长时也会停止；此时它只包含文件的开头部分，标题栏显示 `(tree of the start only)`。`T` 仍会显示全部文本。

## Jupyter 笔记本

`.ipynb` 会逐个单元渲染打开，边框显示 `RENDERED`。顶部显示内核，以及每种单元各有多少。

- Markdown 单元像 Markdown 文件一样渲染。
- 代码单元显示 `In [n]:` 及其代码，使用笔记本语言的颜色。
- 其输出跟在后面，标记为 `Out [n]:`：流的文本（是错误时为 `stderr:`）、结果的文本（或其 Markdown，已渲染），以及带回溯信息的错误，回溯中的 ANSI 代码已去除。
- 图片、HTML、JavaScript、SVG 或 LaTeX 输出显示为一行，说明它是什么以及大小，例如 `[image/png, 34 KiB: not shown]`。笔记本中的任何东西都不会运行：代码、输出中的脚本、小部件都不会。
- raw 单元按原样显示。

`T` 显示笔记本的 JSON，`H` 显示其字节。查看器无法读取的笔记本（JSON 损坏、格式未知）会以源文本打开，并附提示。格式 3（带 worksheets）也能读取。

## Office 文档

Word（`.docx`、`.docm`、`.dotx`）、OpenDocument 文本（`.odt`）、PowerPoint（`.pptx`、`.pptm`）和 Impress（`.odp`）文件会以文档形式打开：标题、段落、列表、表格、粗体、斜体和链接，每个链接都显示其真实地址。演示文稿把每张幻灯片显示在 `Slide n` 下，后面是演讲者备注。脚注和批注连同作者放在最后。图片显示为一行，例如 `[image: media/image1.png]`。文档的文本永远不会被当作 Markdown 解析。

正文之前有一个区块，说明文档除正文外还带了什么，因为其中很多内容在创建它的程序里看不到：

- 谁写的、谁最后保存的、何时、用什么程序；
- 有宏时显示 `Contains macros`。宏永远不会被读取或运行；
- `Fetches from outside when it opens`：指向文件外部的远程模板、OLE 对象或框架，并列出地址。远程模板正是 Follina（CVE-2022-30190）等攻击的入口。这里不会下载任何东西；
- 嵌入的对象（名称和大小），以及其他外部链接的数量；
- 修订：插入的文本显示为 `[inserted: ...]`，删除的文本显示为 `[deleted: ...]`，因为被删除的内容往往才是关键；
- 隐藏文本（`[hidden: ...]`）、白色文本和一磅大小的文本（`[invisible: ...]`），以及隐藏的幻灯片。

`H` 显示字节，再按一次返回；`T` 会说明该文档没有自己的文本。文件的每个部分只解压到一定上限（每部分 64 MiB，总计 256 MiB；Autoview 中为 4 MiB），文档被截断时标题栏会说明。带 DTD 或嵌套超过 256 层的 XML 部分会被拒绝。旧的 `.doc` 和 `.ppt` 仍像以前一样以十六进制打开。

## 电子书

EPUB（`.epub`，第 2 版和第 3 版）和 FictionBook（`.fb2`，以及内部只有一本书的 `.fb2.zip`）以可阅读的书籍形式打开。图片不会显示：每张图片是一行文字，如 `[image: cover.jpg]`。

**书籍。** 打开时先显示扉页：书名、作者、出版者和出版时间、章节数和字数，以及报告中的警告（如果有）。正文是窗口中间的一栏（默认 70 个单元格宽），段落像印刷书籍那样首行缩进，每章标题居中显示在一个装饰图案下方。场景之间的分隔（`* * *`）也画成装饰图案。页脚显示所在章节、在书中的进度，以及本章和全书的剩余时间。

| 按键 | 功能 |
|---|---|
| Space、PgDn | 下一页（PgUp 为上一页） |
| `]` `[` | 下一章或上一章 |
| Tab | 目录：↑↓ 选择，输入字母缩小列表，Enter 跳转，Esc 关闭；之后 Backspace 返回原来的位置 |
| Enter | 在一个框中显示本页引用的注释：↑↓ 滚动，其他任意键关闭 |
| `g` | 跳转到某一行，或书中的某个位置：`40%` |
| `R` | 记住这本书读到的位置；再按一次 `R` 忘记这本书 |
| `I` | 文件的报告，再按一次返回书籍 |
| `Z` | 只显示正文，不显示边框和页脚；Esc 返回 |
| `/` `\` | 向后或向前搜索；`+` 和 `-` 跳到下一个或上一个匹配项（这里 Space 用于翻页） |
| `H` | 显示字节，再按一次返回 |
| Esc | 关闭 |

书中的注释（EPUB 中类型为 footnote 的 `aside`，FB2 中的 `notes` 正文）不在正文里：每处引用显示为上标（`¹`），Enter 显示本页引用的注释。在报告中，注释位于书中原本的位置。

**记住读到哪里。** `R` 记住这本书：关闭时，Xylem 保存您所在的章节和行，下次打开时就从那里开始，并显示 `Back at chapter 7 (R forgets this book)`。被记住的书，页脚以 `[R]` 开头。书是按它自称的身份（其标识符）和大小来识别的，而不是按文件名，因此移动或重命名过的书仍能被认出，而同名的另一个文件则是另一本书。再按一次 `R` 会忘记这本书，并删除为它保存的内容。从未按过 `R` 的书不会留下任何记录。

**阅读时间** 只为用 `R` 记住的书保存，并且需要您开启它（[配置](configuration.md#reading-time)第 5 页的 **E**）。之后扉页和报告会显示您读这本书用了多长时间、分几次阅读、读到哪里、从何时开始；报告还会列出每次阅读。页脚显示本次阅读的时间。

**报告**（`I`）是正文之前对文件本身的说明：书对自己的描述（书名、作者、出版者、语言、日期、标识符、主题、丛书、制作它的程序），以及它除正文外还携带了什么，因为来自任何地方的书，就是来自任何地方的文件：

- 脚本：`<script>` 元素、`onload` 等事件属性、`javascript:` 链接，以及 EPUB 声明含有脚本的部分。这些脚本绝不会运行；而会运行脚本的阅读器则会运行它们；
- 打开书时阅读器会从外部获取的内容：带有互联网地址的图片、样式表、字体和框架，逐一列出。获取它们会让对方知道这本书被打开了，以及在哪里打开。这里不会获取任何内容；
- 表单、框架和嵌入对象的数量，以及指向外部的链接数量；
- DRM：章节被加密的 EPUB 会说明加密方式（Adobe ADEPT、Readium LCP、Apple FairPlay），并且无法阅读。混淆字体在不带 DRM 出售的书中很常见，只做计数；
- 在 EPUB 中：包清单列出但文件中没有的部分、文件中有但清单未列出的部分，以及跳出包之外的地址；
- 在 FB2 中：嵌入其中的文件（数量、类型和大小），这些文件绝不解码；以及它声明了但 Xylem 不认识的编码。

接下来是以链接形式显示的目录（Tab 和 Enter 可跟随链接），然后是全文，注释位于书中原本的位置。

**设置**（[配置](configuration.md)第 5 页）：文本栏的宽度（或整个窗口）、段落首行缩进且紧密相连还是以空行分开、两端对齐，以及计算剩余时间所用的阅读速度。开启 Nerd Fonts（第 2 页的 **M**）后，装饰图案是叶子，进度条用字体自带的字形绘制，页脚和目录也会带上图标。

**读取的内容。** FB2 按其声明的编码读取（UTF-8、UTF-16、Windows-1251、KOI8-R 以及 `O` 中的其他编码），`T` 显示其 XML。EPUB 是一个 ZIP：每个部分只解压到一定上限（每部分 64 MiB，总计 256 MiB；Autoview 中为 4 MiB，书更大时 Autoview 会显示 `V shows it as a book`），FB2 最多读取 64 MiB，只读取了书的开头时报告会说明。绝不读取或获取任何 DTD，带有自定义实体的 XML 会被拒绝，正文绝不会按 Markdown 处理，书中的地址只被当作书自身各部分的名称，绝不当作磁盘上的路径。MOBI 和 AZW3（Kindle）、PDF 以及漫画书（CBZ、CBR）不在这里读取：在文件窗口中按 `O` 用其他程序打开它们。

## Norton Guides

Norton Guide 或 Expert Help 指南（`.ng`），即 DOS 和 Clipper 的超文本帮助，以文档形式打开。文件需要同时具有 `.ng` 文件名和指南的签名；其他文件照旧打开。

- **顶部：** 指南的标题和致谢，以及制作它的程序。
- **菜单：** 每个菜单及其条目，以及每个条目指向哪里。
- **条目：** 按文件中的顺序列出全部条目，每个条目带一个编号：`§12`。列表条目显示其各行；文本条目按指南的排版显示其文本，然后是它的“另请参阅”链接。每个链接都会注明指向哪里（`→ §12`、`See also: Two() §3`），因此搜索 `§12` 就能到达那里。指向不存在之处的链接显示 `(broken link)`。

**跟随链接。** **Tab** 和 **Shift+Tab** 选择下一个或上一个链接（当选中的链接已滚出屏幕时，从屏幕上的链接开始）；**Enter** 前往链接指向的条目，并选中该条目的第一个链接；**Backspace** 返回原来的位置，最多可回溯 1,000 个链接。开启鼠标时，单击链接即可跟随，单击页脚中的 `Backspace` 返回。在指南中，Enter 绝不会关闭查看器：用 Esc 关闭。由于整个指南是一个文档，搜索（`/`）仍会查找全部内容。

粗体、下划线和反色以主题的样式显示；指南的 DOS 颜色不会发送到终端。指南的字符采用代码页 437，字节 1 到 31 显示为 DOS 绘制的字形（`☺ ♥ ► ▲`）；指南中的任何内容都不会作为控制字符到达终端。

指南是一张由偏移量组成的网，而偏移量可能说谎：每个偏移量都与文件核对，每个计数都与其所属记录核对，一行展开成的空格数也有上限。指南中的问题会列在顶部的“Problems in this guide”下，其余内容照常显示。指南整体读取，最多 64 MiB；`H` 显示字节。

能够了解这种格式，要感谢 Dave Pearson：他在 1990 年代弄清了这种格式，此后一直让 Norton Guides 保持可读：<https://www.davep.org/norton-guides/>。Xylem 的阅读器是自己的代码，根据他对格式的描述编写，不包含他的阅读器中的任何代码。

## 可执行文件

可执行文件、库或目标文件，不论名字如何，都会以报告形式打开：ELF（Linux、BSD）、PE（Windows 的 `.exe`、`.dll`、`.sys`，也包括 .NET）和 Mach-O（macOS，也包括含多种架构的通用二进制）。它通过开头的字节识别，从不看名字。报告会说明：

- 它是什么（可执行文件、库、目标文件、core dump），针对哪种机器，32 位还是 64 位，入口点，以及解释器、子系统或最低系统版本；
- **保护措施**，每项为 `yes` 或 `no`，缺少的标记 `⚠`：ELF 上有 PIE、不执行代码的栈（NX）、RELRO（完全或部分）、栈金丝雀、FORTIFY 和库路径（RPATH、RUNPATH：相对路径或位于 `/tmp` 的路径会被标记）；PE 上有 ASLR、高熵 ASLR、DEP、Control Flow Guard；Mach-O 上有 PIE 和可执行栈；
- **签名**：是否有、有多大。签名**不会被验证**，报告也会这样说明；
- 隐藏内容的**迹象**：高熵的节（被打包或加密）、打包器的名字（UPX……）、最后一个节之后的数据（overlay，安装程序和一些恶意软件会把数据放在那里）、同时可写又可执行的节、位于所有可执行节之外的入口点；
- **身份**：build ID、debug link、UUID、PDB 路径、编译器、Go 版本；PE 的构建日期由链接器写入，可以是任意值；
- 它需要的库，以及节、段、导入、导出和符号的列表，每个列表最多 2,000 行。

生成报告时不会运行或加载任何东西：连 `ldd` 也不用，因为它在某些情况下会运行程序。`H` 显示字节，再按一次返回。超过读取上限的文件只在报告需要的地方读取，总共最多 256 MiB；Autoview 只对已读取的开头部分生成报告，并说明可能有遗漏。

## 证书和密钥

证书、证书链或证书包、证书请求（CSR）、吊销列表（CRL）、私钥或公钥、OpenSSH 密钥、`authorized_keys` 和 `known_hosts` 会以报告形式打开。PEM 只在为此命名的文件（`.pem`、`.crt`、`.cer`、`.key`、`.csr`、`.crl`、`.pub`……）或没有扩展名的文件（`id_ed25519`）中读取；DER 只在本身就是一个完整 DER 值的 `.der`、`.cer`、`.crt`、`.crl` 或 `.csr` 中读取。源代码或文档中的 PEM 块不会改变该文件的打开方式。

- **证书：** subject 和 issuer（以及是否自签名）、序列号、有效期和剩余天数（已过期、尚未生效或 30 天内到期的会标记 `⚠`）、公钥（低于 2048 位的 RSA 和 DSA 会被标记）、签名（MD5 和 SHA-1 会被标记）、名称（会指出 punycode 名称 `xn--`）、密钥用途、扩展密钥用途、是否为 CA、其 CRL 和颁发机构信息的地址、未知的关键扩展（会被标记），以及 SHA-256 指纹。
- **多个证书：** 报告会说明它们是否按顺序排列，即每一个都由下一个签发，只按名称和密钥标识符检查。**这里不验证任何签名**，报告也会这样说明。
- **私钥：** 只显示类型和大小（RSA 2048 位、EC P-256、用 PBES2 加密的 PKCS#8……），OpenSSH 密钥还显示是否加密及其指纹。私钥的数值永远不会出现在报告中。在 Autoview 中，私钥只显示这份报告，从不显示其文本，这样光标经过时它也不会出现在屏幕上；在查看器中按 `T` 可显示文本。
- **公钥、`authorized_keys` 和 `known_hosts`：** 每个密钥一行，显示类型和大小、`ssh-keygen -l` 格式的 SHA-256 指纹，以及注释。`command=` 选项会被标记，因为它改变了密钥允许的操作；经过哈希的主机会如实显示。

不会下载任何东西：CRL 或 OCSP 的地址只是显示出来。在任何解析器看到一个块之前，会先检查其嵌套（最多 64 层）和长度；一个文件最多 1,000 个块，每块最多 64 KiB。不读取 PKCS#12（`.p12`、`.pfx`）和 PGP 密钥。

## 日志

日志以文本打开，带有各级别的颜色，页脚显示 `Log`。文件按名称被识别为日志（`.log`、`.out`、`.err`、轮转后的 `app.log.1` 或 `app.log.2.gz`、`syslog`、`messages`、`kern.log`），或按内容识别：开头的大多数行以日期和时间开头（`2026-11-16 10:00`、`[2026-11-16 ...`，或 syslog 的 `Nov 16 10:00:00`）。

- **级别：** 一行前 120 列中第一个级别词（不分大小写）决定其颜色：错误（`ERROR`、`ERR`、`FATAL`、`CRIT`、`PANIC`……）为红色，警告（`WARN`、`WARNING`）为黄色，`DEBUG` 和 `TRACE` 为暗色。行首 syslog 的 `<n>` 也算，JSON 日志的级别（`"level":"error"`）也算。没有级别的行（例如栈回溯）沿用上一行的级别。`C` 关闭颜色。
- **ANSI 颜色：** 程序写入日志的颜色（`ESC [31m`）会显示为颜色，其序列会从文本中去除。其他任何序列都会被丢弃，因为它们可能移动光标或写入剪贴板（OSC 52），标题栏会统计数量，例如 `[ANSI: 3 removed]`。`H` 仍按原样显示字节，搜索针对去除序列后的文本。在超过 16 MiB、通过窗口读取的文件中，这些序列像在任何文本中一样显示为 `·`，颜色则来自级别。
- **跟踪：** 当最后一行在屏幕上时（End），程序写入的新行会随之出现，屏幕保持在末尾；标题栏显示 `[FOLLOW]`。文件每半秒检查一次，网络共享上也一样。向上移动或搜索会停止跟踪；按 End 恢复。有过滤器（`&`）时，新行会经过它。如果文件变小或改变了而不是增长（被轮转或重写），标题栏显示 `(the file changed: R reloads)`，在按 R 之前不会读取任何内容。压缩的日志不会被跟踪。

## 补丁

`.patch` 或 `.diff`，或任何以补丁开头的文本（`diff --git`，或 `---`、`+++` 和 `@@`），会以带补丁颜色的文本打开。Git diff（`D`）也以同样方式显示。标题栏会做汇总，例如 `[12 files, +340 −98]`，页脚说明屏幕顶部所在的位置：`3/12 src/viewer.rs @@ 2/5`。

| 按键 | 操作 |
|---|---|
| `]` `[` | 下一个或上一个文件 |
| `}` `{` | 下一个或上一个 hunk |
| `Tab` | 文件列表，每个文件带 `+` 和 `−`；输入字母可筛选，`Enter` 跳到所选文件 |

有些修改不只是改动行，快速浏览时很容易漏掉。它们以红色显示，标题栏把它们计为 `to check`：

- 变为可执行的文件（`100755`）、符号链接（`120000`）或子模块（`160000`）；
- 绝对路径、用 `..` 向上跳出的路径、进入 `.git` 的路径（hook 是 Git 会运行的代码），或含控制字符、文字方向字符或不可见字符的路径（像 `invoice‮fdp.exe` 这样的名字会隐藏其真实扩展名）。

标题栏还会统计：

- `look unchanged`：一行被删除、一行被添加，二者只在看不见的地方不同，例如空格、`\r`、不可见字符或形似的字母（用西里尔字母 `а` 代替拉丁字母 `a`）。这对行以黄色显示；
- `hunks with wrong counts`：`@@` 行与实际行数不符的 hunk。索引以实际存在的行为准，从不相信这些数字；
- `whitespace`：行尾有空格，或缩进中空格在制表符之前的新增行，与 `git diff --check` 报告的一致。

`git format-patch` 生成的系列会在列表中按主题显示每封邮件。任何内容都不会被应用。在超过 16 MiB、通过窗口读取的文件中，颜色保留，但没有索引：`]`、`}` 和 Tab 会说明这一点。

## 文本方向控制字符

有些不可见字符会改变文本的方向，让代码看起来和它实际的内容不同（Trojan Source，CVE-2021-42574）。查看器从不隐藏它们：每个字符都显示为红色的 `·`，标题栏会告诉您有多少个。

## 文本编码

Xylem 会自己判断编码，顺序如下：先解压文件，再找 BOM（UTF-8、UTF-16 LE 或 BE），再看没有 BOM 的 UTF-16，最后是 UTF-8。如果都不是，就当作旧文本：Xylem 通过统计带重音的字母，在 CP850（DOS，西欧）和 Windows-1252 之间猜一个。Windows 的 `.reg` 导出文件是 UTF-16，会按普通文本打开。

按 **O** 用下一种编码显示文件：UTF-8、CP850、Windows-1252、CP437、Windows-1251、KOI8-R、UTF-16 LE、UTF-16 BE，然后回到 UTF-8。页脚会说明是哪一种，编码不是 UTF-8 时标题里会显示它的名称。如果在以十六进制打开的文件上选 UTF-16，会切换为文本。编辑文件再回来后，您的选择仍然保留。

如果想让旧文本文件总是使用同一种编码，而不是靠猜，把 `legacy_charset` 设为 `cp850`、`cp1252` 或 `cp437`（[配置](configuration.md)第 2 页的 **K**）。默认值是 `auto`。

## 大文件

用 **V** 打开时，磁盘上大于 16 MiB 的文件不会载入：查看器只保留屏幕附近的约 2,000 行，其余的随屏幕移动从文件中读取，不会卡住屏幕。尚未读取的行会短暂显示为 `…`。这样文件就没有大小限制，占用的内存也不会随文件增大。

- **行数在后台统计。** 底部状态栏先显示 `Line 1 of 1,234,567+ (counting…)`，然后显示总数。**End** 和 **g** 可以跳到任何已统计的行。按 Esc 停止统计，已统计的部分保留。
- **搜索**（`F`、`B`、`/`、`\`、Space）在后台遍历文件：底部状态栏显示 `Searching... line 1,200,000 (Esc stops)`，找到匹配项时屏幕会跳过去。
- **行筛选**（`&`）在后台遍历整个文件，找到的行陆续显示，最多 1,000,000 行。按 Esc 停止并保留已找到的行。
- **十六进制**（`H`）读取屏幕所在位置的字节，其搜索同样会遍历文件。
- **切换编码**（`O`）会重新读取各行；切换到 UTF-16 时会重新统计行数，因为行的结束位置不同。
- **没有语法高亮，也没有渲染后的 Markdown**：两者都要从头读取文本。
- **超过 1 MiB 的行** 在屏幕上截断，以 `…` 结尾；十六进制模式会显示全部内容。
- **如果文件在打开期间发生变化**，标题栏会显示 `(the file changed: R reloads)`，按 **R** 重新读取并回到原来所在的行。
- **对文本执行批处理**（`Ctrl+B`）仍会把文件读入内存，最多到下文的大小限制，若未读完整个文件会给出提示。

为了能跳到任意一行，查看器会记下每第 256 行的起始位置，每 256 行约 8 字节，仅保存在内存中。文本方向控制字符随行数一起在整个文件中统计（UTF-8），标题栏显示目前已找到的数量。

压缩文件、归档文件中的条目、远程主机上的文件以及自动预览不会这样读取：无法在其中跳转，因此它们遵循下文的大小限制。

## 大小限制

对于上述情况，以及不超过 16 MiB 的文件，查看器只读取过大文件的开头部分，标题栏会显示 `(showing first N MiB)`。读取多少由选项 `viewer_max_size` 决定（[配置](configuration.md)第 2 页的 **L**）：`auto`、`16`、`64`、`256` 或 `1024`（单位 MiB）。默认的 `auto` 取机器内存的 1/32，但不少于 16 MiB，也不超过 256 MiB（读不到内存大小时为 16 MiB）。配置界面会显示实际使用的值，例如 `auto (256 MiB)`。

有两种情况不遵循这一规则。自动预览（Autoview）始终只读 1 MiB。远程主机（SFTP）上的文件最多读取 16 MiB，因为 Esc 无法取消这种读取。

限制越大，占用的内存和时间越多：设为 `1024` 时，解压后达到这一大小的压缩文本大约占用 2 GiB 内存。很短的行比它们的字节更占内存，因为每一行都有自己的管理开销，制表符和隐藏的文本方向控制字符也是如此：查看器在内存中保留的行最多约为大小限制的两倍，超过后标题栏显示 `(showing first N lines)`。由普通行（约 100 字节）组成的日志不会因此被截断。

## 压缩文件

以 `.gz`、`.xz`、`.zst` 或 `.bz2` 结尾的文件会解压后以文本打开。Xylem 看的是文件的前几个字节，而不是文件名，并且只解一层：`.gz` 里面的 `.gz` 仍保持压缩。标题栏显示 `gzip → N bytes`（格式和解压后的大小）。

解压有限制。查看器最多读取到大小限制，最多用时 3 秒，xz 字典或 zstd 窗口最多占用 64 MiB 内存。自动预览（Autoview）的限制是 1 MiB、100 毫秒和 16 MiB。达到输出或时间限制时，标题栏显示 `(showing first N bytes decompressed)`。一条提示说明发生了什么：

- `decompression stopped after 3 s`（自动预览中为 100 ms）
- `compressed data truncated or corrupt`（压缩数据被截断或已损坏）
- `needs more than 64 MiB of memory to decompress`（自动预览中为 16 MiB；当 V 的 64 MiB 可能够用时，带有 ` (V to view)`）

提示在按下第一个键后消失，但标题栏会保留问题：`(truncated or corrupt)`；内存限制使解压中途停止时显示 `(incomplete: …)`；完全无法解压时显示 `(not decompressed: …)`（此时以十六进制显示原始字节）。

自动预览会在标题中显示这条提示。在十六进制模式（`H`）下看到的是解压后的字节。颜色按去掉压缩扩展名后的文件名决定：`app.rs.gz` 按 Rust 着色。

对于 `.tar.gz`（或 `.tar.xz` 等），提示为 `TAR archive: Alt+F5 opens it as a folder`（按 Alt+F5 可将其作为文件夹打开）。

要查看原始的压缩字节，请关闭 `viewer_decompress`（[配置](configuration.md)第 2 页的 **J**）。

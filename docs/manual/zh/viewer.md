# 查看器

`V` 在查看器中打开文件（自动预览 Autoview，即 F7，则将其显示在文件列表旁）。二进制文件默认以十六进制模式打开。超过大小限制的文件仅显示开头部分。
电子表格、CSV、DBF、SQLite 和 Parquet 以表格形式打开（见“表格模式”）。

| 按键 | 功能 |
|---|---|
| ↑ ↓ PgUp PgDn Home End | 上下滚动 |
| ← → | 左右滚动 |
| `H` | 下一个模式：文本和十六进制；在 Markdown 文件中为渲染、文本和十六进制 |
| `O` | 切换到下一种编码（UTF-8、CP850、1252、CP437、UTF-16） |
| `C` | 开启或关闭语法高亮 |
| `W` | 开启或关闭软换行 |
| `#` 或 `L` | 开启或关闭行号（在文本模式下） |
| `g` 或 `:` | 跳转到指定行（在十六进制模式下为字节偏移量，在表格模式下为表格行） |
| `&` | 只显示匹配的行，纯文本或正则表达式（[筛选行](filter.md)）；表格模式下为 SQL 筛选 |
| Ctrl+B | 为显示的每条记录或每行输出一行（[查看器中的批处理](execute.md)） |
| `E` | 编辑文件；返回 Xylem 后，查看器会在同一位置显示更新后的内容（二进制文件仅在 [`[editors]`](execute.md) 中配置了对应编辑器时可用） |
| `D` | 开启 Git 时：显示自上次提交以来的更改，再次按下返回原内容（[Git](git.md)） |
| `T` | 在以表格形式打开的文件中，切换表格和文本；在 Markdown 文件中，切换渲染和源文本 |
| `U` | 在已标记文件视图（Ctrl+V）中：取消标记该文件 |
| `y` 或 Ctrl+Insert | 将文件路径复制到剪贴板 |
| Esc | 关闭查看器 |

## 搜索

与 ZTreeWin 一致：**F** 从文件开头向后搜索，**B** 从文件末尾向前搜索，**/**（或 `S`）从当前页向后搜索，**\\** 从当前页向前搜索；**Space** 沿同一方向继续查找下一个，**+** 和 **-** 选择搜索方向。匹配项会高亮显示。在搜索提示行中，按 **F2** 切换是否区分大小写（忽略大小写时也会忽略重音符号，如 `AÇÃO` 可匹配 `ação`），按 **F4** 在文本与十六进制（如 `4d 5a` 这样的字节对）之间切换。搜索词中间的 `*` 可匹配同一行内的任意内容（如 `error*disk`）。

## 语法高亮

支持约 150 种语言的源代码和脚本着色（Rust、Python、shell、C、JavaScript、SQL、YAML、Markdown 等），可通过扩展名、文件名（如 `Makefile`）或首行（如 `#!/bin/bash`）自动识别。默认开关由 `syntax_highlight` 设置（见 [配置](configuration.md) 第 2 页）。高亮颜色在当前主题背景上始终保持清晰易读，且仅对前 20,000 行进行语法着色，超过 10,000 个字符的行也不着色，因此超大文件也绝不会拖慢查看器的速度。

## 渲染的 Markdown

`.md` 和 `.markdown` 文件以渲染方式打开，在 Autoview、归档内和压缩文件（`x.md.gz`）中也是如此，边框上显示 `RENDERED`。`T` 在同一位置显示源文本，再按一次返回；`H` 依次切换渲染、文本和十六进制。

可以看到标题、粗体、斜体、删除线、代码、带语法高亮的代码块（`C` 关闭高亮）、嵌套和编号列表、任务列表（`[x]`）、引用、水平线和表格。不会下载任何内容，链接也不会打开任何东西：

- 链接在文字旁边显示真实地址，例如 `safe <https://example.com>`，文字无法冒充另一个地址。
- 图片是一行文字：`[image] 说明 <photo.png>`。
- Mermaid 图是标为 `mermaid` 的代码块。
- HTML 和 HTML 注释保持为可见文本。
- 文件开头的 YAML 块是标为 `yaml` 的代码块。

文本总是适应窗口，因此 `W` 在这里不起作用；← → 可以到达过宽表格的列。搜索查看屏幕上的文本，包括地址，也能找到跨行的短语。`g` 和 `#` 按源文本的行计数。Ctrl+B 作用于源文本的所有行。`&` 切换到文本模式并在其中过滤。

超过 8 MiB 的文件以源文本打开，并显示提示。渲染也会在时间限制（3 秒，Autoview 中为 100 毫秒）或内存限制处停止，此时标题栏显示 `(rendered only the start)`。表格最多显示 256 列。控制字符显示为 `·`，包括写成实体的控制字符，例如 `&#27;`。

Markdown 本身会隐藏一些内容：没有被使用的链接定义，以及超出表头列数的单元格。要查看全部内容，请按 `T` 显示源文本。斜体和删除线取决于终端及其字体，因此它们也有自己的颜色。

## 文本方向控制字符

有些不可见字符会改变文本的方向，让代码看起来和它实际的内容不同（Trojan Source，CVE-2021-42574）。查看器从不隐藏它们：每个字符都显示为红色的 `·`，标题栏会告诉你有多少个。

## 文本编码

Xylem 会自己判断编码，顺序如下：先解压文件，再找 BOM（UTF-8、UTF-16 LE 或 BE），再看没有 BOM 的 UTF-16，最后是 UTF-8。如果都不是，就当作旧文本：Xylem 通过统计带重音的字母，在 CP850（DOS，西欧）和 Windows-1252 之间猜一个。Windows 的 `.reg` 导出文件是 UTF-16，会按普通文本打开。

按 **O** 用下一种编码显示文件：UTF-8、CP850、Windows-1252、CP437、UTF-16 LE、UTF-16 BE，然后回到 UTF-8。页脚会说明是哪一种，编码不是 UTF-8 时标题里会显示它的名称。如果在以十六进制打开的文件上选 UTF-16，会切换为文本。编辑文件再回来后，你的选择仍然保留。

如果想让旧文本文件总是使用同一种编码，而不是靠猜，把 `legacy_charset` 设为 `cp850`、`cp1252` 或 `cp437`（[配置](configuration.md)第 2 页的 **K**）。默认值是 `auto`。

## 大小限制

查看器只读取大文件的开头部分，标题栏会显示 `(showing first N MiB)`。读取多少由选项 `viewer_max_size` 决定（[配置](configuration.md)第 2 页的 **L**）：`auto`、`16`、`64`、`256` 或 `1024`（单位 MiB）。默认的 `auto` 取机器内存的 1/32，但不少于 16 MiB，也不超过 256 MiB（读不到内存大小时为 16 MiB）。配置界面会显示实际使用的值，例如 `auto (256 MiB)`。

有两种情况不遵循这一规则。自动预览（Autoview）始终只读 1 MiB。远程机器（SFTP）上的文件最多读取 16 MiB，因为 Esc 无法取消这种读取。

限制越大，占用的内存和时间越多：设为 `1024` 时，同样大小的普通文本文件大约占用 2.5 GiB 内存，打开约需 5 秒。很短的行比它们的字节更占内存，因为每一行都有自己的管理开销，制表符和隐藏的文本方向控制字符也是如此：查看器在内存中保留的行最多约为大小限制的两倍，超过后标题栏显示 `(showing first N lines)`。由普通行（约 100 字节）组成的日志不会因此被截断。

## 压缩文件

以 `.gz`、`.xz`、`.zst` 或 `.bz2` 结尾的文件会解压后以文本打开。Xylem 看的是文件的前几个字节，而不是文件名，并且只解一层：`.gz` 里面的 `.gz` 仍保持压缩。标题栏显示 `gzip → N bytes`（格式和解压后的大小）。

解压有限制。查看器最多读取到大小限制，最多用时 3 秒，xz 字典或 zstd 窗口最多占用 64 MiB 内存。自动预览（Autoview）的限制是 1 MiB、100 毫秒和 16 MiB。达到输出或时间限制时，标题栏显示 `(showing first N bytes decompressed)`。一条提示说明发生了什么：

- `decompression stopped after 3 s`（自动预览中为 100 ms）
- `compressed data truncated or corrupt`（压缩数据被截断或已损坏）
- `needs more than 64 MiB of memory to decompress`（自动预览中为 16 MiB；当 V 的 64 MiB 可能够用时，带有 ` (V to view)`）

提示在按下第一个键后消失，但标题栏会保留问题：`(truncated or corrupt)`；内存限制使解压中途停止时显示 `(incomplete: …)`；完全无法解压时显示 `(not decompressed: …)`（此时以十六进制显示原始字节）。

自动预览会在标题中显示这条提示。在十六进制模式（`H`）下看到的是解压后的字节。颜色按去掉压缩扩展名后的文件名决定：`app.rs.gz` 按 Rust 着色。

对于 `.tar.gz`（或 `.tar.xz` 等），提示为 `TAR archive: Alt+F5 opens it as a folder`（按 Alt+F5 可将其作为文件夹打开）。

要查看原始的压缩字节，请关闭 `viewer_decompress`（[配置](configuration.md)第 2 页的 **J**）。

## 表格模式

有些文件以网格而不是文本形式打开。Xylem 根据扩展名判断，且仅限本磁盘上未压缩的文件：远程机器上或压缩包内的文件显示为普通内容，并给出提示 `Tables are shown only for files on this disk`。

| 格式 | 扩展名 | 列名 |
|---|---|---|
| CSV、TSV | `.csv` `.tsv` `.tab` | 第一行（至少一半内容不是数字时）；否则为 A、B、C... |
| JSON Lines | `.jsonl` `.ndjson` | 对象的键 |
| 电子表格 | `.xlsx` `.xls` `.xlsb` `.ods` | A、B、C...（第一行与其他行相同） |
| dBase、Clipper、FoxPro | `.dbf`，以及其备注文件 `.dbt` | 字段名 |
| SQLite | `.db` `.sqlite` `.sqlite3` | 数据表的列 |
| Parquet | `.parquet` | 文件的列 |

CSV 的分隔符（逗号、分号、制表符或竖线）根据文件开头自动检测。

| 按键 | 功能 |
|---|---|
| ↑ ↓ | 上一行或下一行 |
| ← → | 上一列或下一列 |
| PgUp PgDn | 向上或向下翻一页 |
| Home End | 第一列或最后一列 |
| `[` `]` | 电子表格的上一个或下一个工作表，或 SQLite 数据库的上一个或下一个数据表，循环切换；这会清除筛选 |
| `Tab` | 工作表或数据表列表：输入名称的一部分可缩小列表，Enter 打开，Esc 返回；打开另一个会清除筛选。在数据库中，视图排在数据表之后，并标有 `(view)` |
| `g` 或 `:` | 按文件中的行号跳转；如果该行被筛选隐藏，则跳到下一个保留的行 |
| `\` 或 `&` | SQL 筛选 |
| `m` 或 Insert | 标记或取消标记光标所在记录并移到下一条；之后 **Ctrl+B** 只写入已标记的记录 |
| `M` | 清除标记 |
| `T` | 切换到文件的文本，再切换回来 |
| `H` | 从表格到文本，然后到十六进制，再回到表格 |

有多个工作表或数据表时，边框显示 `TABLE [2/5: 名称]`；底部一行显示光标位置：`Cell B7 (Row 7 of 120)`。筛选时，各行保留其在文件中的行号，这一行还会显示是第几个匹配：`Cell A13 (Row 13 of 31, match 2 of 8)`。网格的最后一行显示单元格的完整内容和当前筛选。搜索（`F`、`B`、`/`）不会查看网格内容，在这里什么也找不到；它在文本模式下可用。

标记在筛选下仍然保留，Batch 写入已标记且被筛选保留的记录。标记属于当前打开的工作表或表，切换后会丢失。如果标记后文件发生变化，Batch 会拒绝执行，因为这些位置可能已是其他记录。

### SQL 筛选

`\` 或 `&` 会要求输入条件，写法类似 SQL 的 `WHERE`（`WHERE` 一词可省略），并只显示满足条件的行。提示符中预先填入当前筛选；留空即可重新显示所有行。提示信息会显示 `Filter matched N rows` 或 `SQL error: ...`；出错后，之前的筛选仍然有效。

```
age >= 30 AND name LIKE 'Ali%'
WHERE status IN ('open', 'late') OR total > 1000.50
NOT (city = 'Rio' OR city IS NULL)
B ILIKE '%silva%'
```

| 运算符 | 功能 |
|---|---|
| `=` `!=` `<>` `<` `<=` `>` `>=` | 比较 |
| `AND` `OR` `NOT` 和括号 | 组合条件（`AND` 优先于 `OR`） |
| `LIKE` `ILIKE` | 匹配模式，`%` 表示任意文本，`_` 表示一个字符；`ILIKE` 忽略大小写 |
| `IN (...)` `NOT IN (...)` | 在或不在列表中 |
| `IS NULL` `IS NOT NULL` | 单元格为空或不为空 |

关键字不区分大小写。

- **列：** 列名（不区分大小写，不加引号），或其字母 `A` 到 `Z`。名称含空格或符号时，可用字母引用。不存在的列视为空，不会报错。
- **值：** 单引号或双引号中的文本（其中的引号写作 `\'`）、数字、`TRUE`、`FALSE` 和 `NULL`。引号中的内容始终是文本，绝不是列。
- **单元格：** 类型取决于单元格的内容形式。空单元格为 `NULL`，`true` 和 `false` 是布尔值，数字就是数字，其余为文本。因此请写 `code = 7`，而不是 `code = '7'`：文本和数字永不相等，内容为 `007` 的单元格就是数字 7。文本比较区分大小写。
- **长度：** 筛选条件最多 1024 字节、128 个词项。

### 在数据库中运行完整查询

在 SQLite 数据库中，同一个提示符也接受以 `SELECT` 或 `WITH` 开头的完整查询，可使用 SQLite 的全部功能：`JOIN`、`GROUP BY`、`ORDER BY`、函数。

```
SELECT c.name, sum(o.price) FROM customers c JOIN orders o ON o.code = c.code GROUP BY c.name
```

边框显示 `QUERY:`，网格显示结果。之后输入条件可筛选这些行，**Ctrl+B** 会写入查询给出的全部结果。提示符留空先清除筛选，再回到数据表；`Tab`、`[` 和 `]` 也会回到数据表。查询只能读取，且一次一条：其他内容都会被拒绝，出错时屏幕保持原样。下面的限制同样适用，因此较慢的查询在 3 秒时停止并显示已得到的行；Batch 没有这个限制。 Xylem 不会修改数据库：`UPDATE`、`DELETE` 等会收到说明此事的消息。要修改数据库，请使用其他程序：在文件窗口按 `O` 用 `opener` 设置的程序打开，在 `[editors]` 中写 `'*.db' = 'sqlite3 %f'` 可让 `E` 用 `sqlite3` 打开。

### 限制

一个表格最多容纳 50,000 行和 256 列，耗时也不超过查看器其他限制所允许的范围：3 秒（自动预览中为 100 毫秒）；解压后超过大小限制（自动预览中为 1 MiB）的电子表格不会以表格形式打开。超出部分不会显示，筛选也看不到，标题栏会提示：`(showing first 50,000 rows)` 或 `(stopped by the time limit: showing N rows)`。读取表格时屏幕保持可用，并有提示说明；按 Esc 停止读取并显示已读到的内容，`(stopped by Esc: showing N rows)`，再按一次 Esc 关闭查看器。单元格最多显示 2,048 个字符，之后显示 `…`。控制字符和文本方向字符显示为 `·`。

## 由 C 库读取的表格

SQLite 数据库（`.db`、`.sqlite`、`.sqlite3`）和 Parquet 文件由 C 语言编写的库读取，不具备 Rust 的内存安全性。因此，只有按 `V` 才会以表格形式打开。Autoview 会读取光标经过的所有文件，并将这些文件显示为普通内容，同时给出提示 `Parquet or SQLite: V opens the table`。只有在接受此风险时，才打开来源不可信的数据库。

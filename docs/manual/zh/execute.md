# 编辑、执行与批处理

## 编辑 Edit (E)

在编辑器中打开文件：优先使用 [配置](configuration.md) 第 1 页中设置的编辑器，否则依次尝试 `$VISUAL`、`$EDITOR`、Debian 与 Ubuntu 的 `editor`，或 `vi`。

默认情况下，编辑器会在 **Xylem 的界面框架内** 打开（**F12** 第 1 页中的 `editor_in_frame = true`），并使用 **Xylem 的配色主题**（`editor_theme = true`）；当编辑器为 `vi`、`vim` 或 `nvim` 时，语法高亮与界面颜色也会与当前主题保持一致。若想将整个终端交给编辑器，请设置 `editor_in_frame = false`；若想保留编辑器自带的配色方案，请设置 `editor_theme = false`。

### 二进制文件与按文件类型指定编辑器

文本编辑器打开图片或可执行程序只会显示乱码甚至损坏文件，因此 `E` 绝不会用文本编辑器打开 **二进制文件**（即开头附近含有空字节、查看器以十六进制显示的文件）。

取而代之的是，当启用了 **Edit binary files with E**（**F12** 第 1 页中的 `edit_binary = true`，快捷键 **I**）时，按 `E` 会使用十六进制/二进制编辑器打开二进制文件：

1. `[editors]` 中匹配到的文件名模式（如有），或
2. **F12** 第 1 页中设置的 **Binary editor**（`binary_editor`，快捷键 **J**）或 `[editors]` 中的 `binary`，或
3. 若留空，则自动使用在 `PATH` 中找到的第一个终端十六进制编辑器：
   - **Linux**：`hexedit`、`heh`、`bvi`、`dhex`
   - **Windows**：`heh`（`winget install ndd7xv.heh`）、`hexedit`、`bvi`

终端十六进制编辑器的运行方式与文本编辑器相同：默认在 **Xylem 的界面框架内** 打开（`editor_in_frame = true`），并使用 **Xylem 的配色主题**（`editor_theme = true`）。对于希望在独立窗口中运行的图形界面十六进制编辑器（Linux 上的 `ImHex`、`GHex`、`Okteta`；Windows 上的 `ImHex`、`HxD`），请在命令末尾加上 `&`（例如 `imhex %f &` 或 `ghex %f &`）：Xylem 会直接后台启动它，而不打开终端框架。

如果您不希望 `E` 打开任何二进制文件（仅在底部状态栏给出提示并建议按 `O` 调用系统程序打开），只需将 **Edit binary files with E** 设为 `no`（**F12** 第 1 页中的 `edit_binary = false`）。

若要为特定类型的文件指定专用编辑器，请在 `config.toml` 的 `[editors]` 表中列出：

```toml
[editors]
"*.png *.jpg *.jpeg *.gif" = "gimp %f &"
"*.md" = "typora %f &"
"*.svg" = ""            # 留空：即使匹配也使用常规编辑器
binary = "hexedit"      # 所有其他二进制文件的后备编辑器
```

每个键都是文件名模式列表，规则与 [Filespec](filespec.md) 相同（不区分大小写）；每个值是一条命令行，其中 `%f` 代表文件路径（若省略 `%f`，文件路径会追加在命令末尾）。按配置文件中的顺序，第一个匹配的键生效。当 `binary_editor` 为空时，`binary` 用于匹配未被任何模式命中的其他二进制文件；其余文件则在常规文本编辑器中打开。

Xylem 没有内置十六进制编辑器，这是有意为之的设计选择：自己开发并维护一个需要大量工作却很少用到，而且手动修改字节极易损坏文件。相反，Xylem 将专门的十六进制编辑器无缝集成在自己的界面框架和配色主题中——如果您不需要这项集成，也可以在 **F12** 中一键关闭二进制文件编辑。

## 执行 eXecute (X)

提示输入命令行，并在当前目录中用 `sh` 执行。在命令中可使用以下占位符：

| 占位符 | 含义 |
|---|---|
| `%f` | 光标下的文件 |
| `%t` | 所有已标记的文件 |
| `%d` | 当前目录 |
| `%%` | 字面量 `%` |

所有路径都会自动加上引号，例如：`tar czf backup.tgz %t`。命令执行完毕后，Xylem 会等待您按 Enter 以便查看输出，随后重新读取已打开的目录。以 `@` 开头的命令不会保存在历史记录中（当启用 `history_skip_at` 时）。

对于需要连续交互的操作，使用 [内置终端](terminal.md)（Alt+X）通常更加方便。

## 批处理 Batch (Ctrl+B)

先提示输入要创建的文件名（按 F2 可 [选择文件夹](picker.md)），再提示输入行掩码，然后为每个已标记的文件写入一行。可用参数：

| 参数 | 含义 |
|---|---|
| `%f` | 完整路径 |
| `%d` | 所在目录 |
| `%n` | 文件名 |
| `%b` | 不含扩展名的文件名 |
| `%e` | 扩展名 |
| `%s` | 大小 |

小写参数会自动加上适合 shell 的安全引号（如 `convert %f %b.png`）；大写参数则输出纯文本，适合生成列表（如 `%N;%S`）。若文件名为 `.sh` 结尾，会自动添加 `#!/bin/sh` 并赋予可执行权限（可用 `X` 运行）。不会覆盖已存在的文件。

## 查看器中的批处理

在[查看器](viewer.md)中打开表格或文本时，**Ctrl+B** 按整个文件为每条记录写一行：不受屏幕 50,000 行的限制，值完整且与文件中完全一致。它遵循当前的筛选（表格的 SQL 筛选、文本的[行筛选](filter.md)）。表格在执行时重新读取；文本按查看器读取的内容输出，最多到大小限制；如果这不是整个文件，预览会发出警告。它会先询问文件，再询问掩码，并在写入前显示前几行：**Enter** 写入，**Esc** 放弃。写入过程中，Esc 取消并删除不完整的文件。已有文件不会被覆盖。

输入掩码时，上方的方框会显示一个适用于此文件的掩码、它的字段以及你已有的模板，每个模板都附有其开头注释（`%%#`）的第一句话。**↑↓** 选择模板，**F3** 在使用前显示完整内容，**PgUp**/**PgDn** 浏览历史记录。描述由模板作者编写：使用他人的模板前，请先用 F3 阅读。掩码有错误时，提示框保持打开并保留已输入的内容，同时说明问题所在。

| 字段 | 值 |
|---|---|
| `%{name}` `%{A}` `%{2}` | 表格的列，按名称、字母或位置 |
| `%{line}` | 文本的整行，保留制表符 |
| `%{ip}` `%{1}` `%{0}` | 行筛选正则表达式的分组，按名称或编号；0 为它匹配的全部内容 |
| `%{#}` | 记录在已写入记录中的序号：1、2、3... |
| `%{#line}` | 行在文件中的行号（仅文本） |
| `%{#path}` `%{#dir}` `%{#name}` `%{#base}` `%{#ext}` `%{#size}` | 打开的文件，与其他字段一样经过转义；上面的 `%N` 等没有转义，因此在页面或脚本中请优先使用这些 |
| `%{$NAME}` | 环境变量，例如 `%{$PATH}`，取当前值；预览会列出读取的变量，不存在的变量会报错 |
| `%{#date}` `%{#time}` `%{#datetime}` `%{#utc}` | 当前时间，本地时间（`#datetime` 含时区）或 UTC：所有记录相同 |
| `%{#year}` `%{#month}` `%{#day}` `%{#weekday}` `%{#weekday_name}` `%{#epoch}` | 其各部分：星期 1 为星期一，名称为英文，epoch 为自 1970 年起的秒数 |
| `%{#user}` `%{#host}` `%{#template}` `%{#output}` | 生成者、所用机器、所用模板，以及写入的文件 |
| `%f %d %n %b %e %s` | 打开的文件，与上面的批处理相同 |
| `%%` | 一个 `%` |

不存在的字段在预览中报错，绝不会输出空值。由于预览最多查看 1,000 条记录，只在其后出现的 JSON Lines 键视为不存在。

这些值来自可能带有恶意的文件，又可能进入你将要运行的内容，因此每个字段都有转义方式。写在字段之后：`curl "https://api/x?id=%{id:url}"`。

| 转义 | 用于 | 默认用于 |
|---|---|---|
| `:sh` | shell 命令中带引号的一个参数 | `.sh` `.bash` `.zsh` |
| `:url` | URL 的一部分，百分号编码 | |
| `:json` | JSON 值：数字不带引号，文本带引号 | `.json` `.jsonl` `.ndjson` |
| `:xml` 或 `:html` | 文本或属性 | `.xml` `.html` `.htm` `.xhtml` `.svg` |
| `:sql` | 带引号的字面量、`NULL`、`X'00ff'` | `.sql` |
| `:mysql` | 同上，用于 MySQL 和 MariaDB，其中反斜杠也用于转义 | |
| `:csv` | 一个字段，必要时加引号 | `.csv` `.tsv` |
| `:csvsafe` | 同上，并在电子表格可能视为公式的内容前加 `'` | |
| `:line` | 值本身，控制字符变为空格，因此不会另起一行 | 其他 |
| `:raw` | 原样输出：**不要用于脚本** | |

- Blob 以十六进制输出，但 `:raw` 除外，`:sql` 有其自己的形式。
- 对于 MySQL 和 MariaDB，请使用 `:mysql`，并以 `utf8mb4` 读取文件：在其中，`:sql` 字面量里的反斜杠可能会将其闭合，预览会对这些值发出警告。如果服务器启用了 `NO_BACKSLASH_ESCAPES`，则应使用 `:sql`。
- 在 SQL 中，字符串内的 `%f %d %n %b %e %s` 会被拒绝：`LIKE '%foo%'` 会带上打开文件的路径。要得到 `%` 请写 `%%`，例如 `LIKE '%%foo%%'`；要得到该值请使用 `%{#name}` 这样的字段。
- 表格的筛选适用于整个文件，规则与屏幕相同：`code = 7` 也会找到内容为 `007` 的单元格，输出仍为 `007`。因此文件中可能有屏幕（限 50,000 行）未显示的行。
- `.sh` 以 `#!/bin/sh` 开头，但**不会获得执行权限**：请先阅读再运行。`.bat` 和 `.cmd` 会被拒绝，因为 `cmd` 即使在引号内也会展开 `%VAR%`。
- 预览和最后的消息会提示含控制字符或文本方向字符的值，以及 CSV 中以公式开头的值。预览只统计它查看过的内容。

### 完整记录

对于 `.json`、`.jsonl`、`.ndjson`、`.csv`、`.tsv`、`.xml`、`.html` 或 `.htm` 文件，将掩码**留空**即可按该格式的规则写入完整记录：对象组成的 JSON 数组、每行一个对象、带表头的表格、每条记录一个 `<record>`，或包含表格的页面。若只写部分字段，请以 `@` 开头：`@id, name, #`。文本提供 `line_number`、`line` 和筛选的分组。字段从前 1,000 条记录中确定：之后才出现的 JSON Lines 键不会写入，最后的消息会说明。

`.db`、`.sqlite` 或 `.sqlite3` 文件也接收完整记录，写入表 `records`，并拒绝掩码和模板。每个值保持其类型：列没有声明类型，因此 CSV 中的 `007` 仍是 `007`。也因此 CSV 的值是文本；要按数字比较，请使用 `CAST(balance AS REAL)`。

### 模板

用于试用这些功能的文件位于仓库的 [demo/](https://github.com/andrelnfernandes/xylem/tree/main/demo) 中：所有格式的相同客户数据，以及现成的模板。

如需在记录周围添加文本，请将模板保存为 `~/.config/xylem/batch/name.tpl`，并输入 `:name` 作为掩码；提示符会列出找到的模板（前四个）。

```
%%# 注释
%%header
<h1>%{#name}</h1>
<ul>
%%record
<li><a href="https://x/?id=%{id:url}">%{name}</a></li>
%%footer
</ul>
```

`%%header` 和 `%%footer` 是可选的，只能包含模板文本和打开文件的字段。`%%record` 每条记录写入一次，可以有多行；没有分节时，整个文件就是记录。转义方式与掩码一样取决于输出文件，因此页面模板应写入 `.html`。不存在的分节、重复的分节，或页眉页脚中的记录字段，都会在预览中报错。预览显示页眉的最后 3 行。没有记录时不写入任何内容。

在记录中，`%%if 条件`、`%%else` 和 `%%end` 选择要写入的内容，`%%stop if 条件` 在此处结束文件，并保留页脚。条件的写法与 [SQL 筛选](viewer.md)相同，可使用记录的字段以及 `#` 和 `#line`：

```
%%record
%%stop if # > 100
%%if balance < 0
%{name} 欠款 %{balance}
%%else
%{name} 正常
%%end
```

`%{#}` 是记录在已读取内容中的位置；`%{count}` 和最后的消息只统计写入了内容的记录。预览只读取前 1,000 条，并会说明哪些分支没有被任何已查看的记录走过。以 `%%if ` 或 `%%stop if ` 开头的行始终是这些命令之一。

在页脚中，`%{sum:列}`、`%{min:列}`、`%{max:列}` 和 `%{avg:列}` 以精确小数统计已写入的记录。数字按 `1234.56` 读取；其他文件需说明写法：`1.234,56` 用 `%{sum:值:br}`，`1,234.56` 用 `%{sum:值:us}`，总计也按相同格式输出。空值不计入；不是数字的值会被排除，并在最后的消息中计数。

在页脚中，`%{count}` 是写入的记录数。页眉不能使用它，因为页眉在读取记录之前写入。

在 `.sh` 中，`%{$HOME}` 写入当前值，而 `$HOME` 在脚本运行时读取。他人的模板就是他们的脚本：它可能把 `%{$SECRET:url}` 放进命令，因此请查看预览所说的读取内容。

## 历史记录

在任何提示行中，按 ↑ 和 ↓ 可调出之前的输入记录。每种提示行（Filespec、目标路径、Log、eXecute 等）都有各自独立的历史记录，保存在 `~/.local/state/xylem/history.toml` 中；由于其中可能包含您输入过的命令，该文件仅对您本人可读。

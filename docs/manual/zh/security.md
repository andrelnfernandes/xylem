# 安全

Xylem 将非自身创建的所有外部文件均视为潜在恶意文件：下载的文件、打开的归档、远程服务器发送的文件名、克隆的仓库等。任何文件的内容或名称绝不应导致 Xylem 崩溃、卡死、执行代码、越界写入或耗尽内存。如果发生上述情况，均属于应予报告的缺陷。

## Xylem 采取的防护措施

| 风险 | 防范措施 |
|---|---|
| 恶意文件利用解析器漏洞 | 文本、十六进制、编码转换、压缩文件、归档、Markdown、电子表格、CSV、JSON Lines 与 DBF 均由 Rust 编写的解析器读取。SQLite 与 Parquet 由 C 编写的库读取，且仅在您明确按 `V` 打开文件时才会读取，绝不在 Autoview 自动预览中读取。 |
| 文件触发执行外部程序 | 除非您明确使用 `E`、`O` 或 `X`，否则绝不会针对文件自动运行任何外部程序。 |
| 小文件解压膨胀耗尽内存或磁盘 | 每个读取器都限制读取量、解压量、耗费时长以及解压占用的内存。仅解开单层压缩。查看文件绝不向磁盘写入任何数据。 |
| 文件名伪装隐藏真实属性 | 控制字符与双向文本控制符（Trojan Source）绝不会直接输出到终端。含有隐藏方向字符的文件名以红色警示，按 `O` 打开前会再次提示确认。 |
| 归档文件越界提取覆盖外部路径 | 包含 `..` 的路径与绝对路径均会被拒绝，归档中的符号链接不会被提取，且自动移除 setuid 权限位。SFTP 服务器发送的文件名同样接受相同的校验。 |
| Git 仓库运行它自己的命令 | 浏览仓库绝不运行 hooks、`core.fsmonitor`、外部 diff 或文本转换工具，除非该目录已列入 `git_trusted`。 |
| 依赖项存在已知安全漏洞 | CI 流程中依据 RustSec 数据库对所有依赖项进行安全审核。 |

## 用户防范建议

- 如果在不可信目录中使用 Autoview，可在查看器中关闭自动解压功能（`viewer_decompress = false`，F12 第 2 页），或保持 Autoview 关闭。
- 在非本人创建的代码仓库中，保持 Git 处于关闭状态（默认即为 `git = false`）。
- 切勿以 root 超级用户权限运行 Xylem。
- `O` 会将文件转交给外部程序打开，此时 Xylem 的安全防护边界不再适用于该外部程序。

## 未涵盖的范围

- 由 `E`、`O` 与 `X` 启动的外部程序。
- 系统中安装的 `rclone`、`ssh`、`docker` 与 `git` 本身。
- 终端模拟器自身在解析接收到的文本时可能存在的漏洞。
